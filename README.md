## 简介

一个跨平台的视频资源下载油猴脚本。B 站走原生解析，抖音、快手、小红书、微博、今日头条、X (Twitter) 走内容解析，配套下载队列、ZIP 打包与智能诊断反馈。**仅供个人学习研究使用。**

---

## 特性

| 特性                    | 说明                                                   |
| --------------------- | ---------------------------------------------------- |
| **七平台解析**             | B 站（普通 / 分P / 番剧 / 合集）、抖音、快手、小红书、微博、今日头条、X (Twitter) |
| **B 站原生下载**           | 清晰度与音频编码选择、封面、字幕、弹幕下载                                |
| **本机 FFmpeg 桥接**      | 文件交给本机原生 ffmpeg 合并，突破浏览器内存与 wasm 性能瓶颈                |
| **Motrix / aria2 投递** | 支持把下载任务投递给 Motrix（aria2/RPC），失败自动熔断回退至浏览器下载          |
| **轻量 GIF 编码器**        | 内置 BAYER 抖动 + LZW 压缩 + 调色板量化，无第三方库                   |
| **下载队列**              | 下载中再点自动入队，去重，队列上限 8                                  |
| **ZIP 打包**            | 选中项超过 15 个自动打包下载                                     |
| **智能诊断**              | 全局错误钩子 + 环境快照 + 自动脱敏，一键复制报告                          |

## 安装

### 1. 安装脚本

在脚本管理器中新建脚本 → 粘贴脚本内容 → 保存。跨域权限提示请允许。

### 2. 安装本地 FFmpeg 桥接（可选）
FFmpeg本地文件下载地址：https://github.com/motrixapp/ffmpeg-static/releases/tag/v9.0.2-motrix.8
不装也能用，脚本会自动回退到浏览器内合并。

1. `node -v` 确认已安装 Node.js。
2. 把 `ffmpeg-bridge.js` 与 `启动FFmpeg桥接.bat` 放在同一目录。
3. 双击 `启动FFmpeg桥接.bat`。
4. 看到 `ffmpeg-bridge 已启动 http://127.0.0.1:16888` 即成功，**保持窗口开启**。

指定自己的 ffmpeg：

```bash
node ffmpeg-bridge.js "D:\你的路径\ffmpeg.exe"
```

### 3. 接入 Motrix（可选）

Motrix → 设置 → 开启 RPC（端口 `16800`）→ 脚本内填写主机 / 端口 / 令牌 → 测试连接。

## 使用说明

### 哔哩哔哩

适用页面：`bilibili.com/video/*`、`bilibili.com/bangumi/play/*`

1. 打开视频页 → 点击下载入口 → 选择参数 → 开始下载。
2. 默认只下载当前分 P；**连续点击底部免责声明区域 5 次**解锁多选。

> 可选的清晰度与音频编码取决于账号权限，不破解会员限制。

### 短视频平台

打开内容页 → 点击浮动入口 → 等待解析 → 下载视频 / 图集 / 实况图 / 封面 / 音频。  
下载中再次点击会**加入队列**，重复内容不入队。

## 故障排查

| 问题         | 处理                                                |
| ---------- | ------------------------------------------------- |
| 解析失败       | 刷新页面，确认视频能正常播放                                    |
| 下载失败       | 检查跨域权限是否已授予                                       |
| 清晰度不可选     | 账号无该清晰度权限                                         |
| 合并失败       | 改用分离下载，或用本机 ffmpeg 手动合并                           |
| 桥接连不上      | 确认`ffmpeg` 相关文件无损坏，`ffmpeg-bridge.js` 窗口开启、端口未被占用 |
| 桥接报路径错     | 用 `node ffmpeg-bridge.js "你的路径"` 显式指定             |
| Motrix 连不上 | 检查 RPC 是否开启、端口是否为 `16800`                         |
| Motrix 卡住  | 连续点击 5 次自动回退，或手动关闭 Motrix 通道                      |

手动合并：

```powershell
ffmpeg -i "input_video.mp4" -i "input_audio.m4a" -c copy "output_merged.mp4"
```

收集诊断报告：面板「智能诊断」→ 填写现象 → 复制报告 / 提交到 GitHub（敏感字段已自动脱敏）。

## 已知限制

- 清晰度取决于账号权限，不破解付费、DRM 或权限受限内容。
- 大文件合并占用较多内存。
- 短视频解析依赖页面数据与站点接口，接口变更、风控、改版都可能导致失败。
- 快手 `new-reco` 非作品 URL，成功率取决于页面暴露程度。
- 本地桥接为明文 HTTP 且允许任意来源 CORS，仅监听 `127.0.0.1`，**切勿改成 `0.0.0.0`**。
- 原版压缩后代码可读性差；本版为展开格式，体积更大但可维护。

### 未经验证的范围

以下链路**未在真实浏览器 + 真实脚本管理器中做过端到端实跑**，结论只到「语法通过 + DOM 注入无抛错」这一层：

- 桥接合并的**实际落盘结果**与 350 MB 上限表现
- Motrix / aria2 RPC 的**真实投递与熔断**行为
- GIF 编码器产出文件的**逐帧正确性**

> 若你实测发现与上表不符，请用「智能诊断」导出报告后反馈。
